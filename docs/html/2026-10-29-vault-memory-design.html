Vault 장기기억 설계

기억은 Vault 안의 Markdown 파일로 남깁니다. Vault는 파일과 함께 그 파일을 쓰는 도구(llm-wiki의 tools/wiki, MCP 서버, 스킬)를 품고 있습니다. 프로젝트와 Vault의 연결은 vault-builder가 사용자 범위($HOME/.claude/vault-builder/)에 두는 vault-map.json에 적혀 있습니다. vault-graph는 Vault를 기반으로 한 Claude Code용 장기 기억 도구입니다. 이 파일을 읽어 프로젝트에 연결된 여러 Vault를 함께 검색하고, 세션 시작 때 고정 기억부터 회상을 넣고, Vault 자체 도구를 실행해 기억을 추가·수정·폐기·제안하며, 세션 원문 수집의 실행 시점을 정합니다.

상태 2026-10-29 제안 · 2026-11-02 구현 반영(장기 기억 흐름, 상세는 docs/specs/2026-11-02-vault-long-term-memory/spec.md) · 중립 검토 2건 모두 ISSUES(차단 없음)
  • 원본은 Vault 하나기억은 사람이 Obsidian에서 읽고 고칠 수 있는 파일입니다. vault-graph 색인은 지워도 다시 만들 수 있습니다.
  • wiki/는 검증을 거쳐서만 바뀜정리와 vault-graph 쓰기 도구는 Vault 도구의 검증(publish-draft)을 거쳐 wiki/에 기록됩니다. 추론한 사실은 사람이 승인해야 기록됩니다. 세션 수집기는 raw/sessions/에 새 턴만 덧붙입니다(결정11). vault-graph는 Vault 파일을 직접 쓰지 않습니다.
  • vault-graph는 LLM을 부르지 않음근거와 출처만 돌려주고, 추론은 호출한 에이전트가 합니다. 로컬에서만 돌고 비용이 없습니다.
역할과 가치 현재 구현 상태 장기 기억 흐름 방향 전체 구조도 기능 목록 그룹별 세부 구조 에이전트와의 상호작용 위험 중립 검토 남은 결정과 단계

01역할과 가치

Vault는 기억을 저장하고, 검증을 거쳐 씁니다. vault-graph는 그 위에서 찾는 일을 맡습니다. Vault가 작을 때는 Vault 검색으로 충분합니다. 세션 원문이 수천 개로 늘고, Vault가 여러 개가 되고, 코드 저장소까지 함께 봐야 할 때 vault-graph가 필요해집니다.

02+장기 기억 흐름 (2026-11-02 구현)

아래 네 흐름은 브랜치 feat/jh/local-graph에 구현된 동작입니다. 기존 Vault는 vault-builder의 계약 버전 4 마이그레이션을 적용해야 쓰기가 되고, vault-builder install --with-hooks로 훅을 설치해야 회상과 수집 시점이 실제 세션에 들어갑니다.

흐름누가 무엇을 하나결과
여러 Vault 검색 · 표시범위를 주지 않으면 cwd의 프로젝트에 연결되고 Graph Home에 등록된 Vault 전부를 찾습니다. 프로젝트가 없으면 활성 Vault 하나를 찾습니다. MCP search_vault · ask_vault · build_context_pack은 선택 입력 cwd를 받고, 없으면 MCP 서버의 작업 디렉터리를 씁니다. 종류 사이 고정 우선순위는 없습니다.관련도 순 한 목록. 검색 결과마다 vault_name · vault_role이 붙고, CLI는 줄 앞에 [이름·종류]를 붙입니다. 프로젝트 Vault가 하나도 등록되지 않았으면 다른 Vault로 넘어가지 않고 "vg setup 필요" 경고를 냅니다. 폐기(retired) 페이지는 기본 검색에서 빠집니다.
추가 · 수정 · 폐기 · 제안에이전트가 MCP remember(추가), update_memory(본문 교체), retire_memory(폐기)를 부르고 basis를 반드시 줍니다. 새 페이지의 저장 Vault는 vault, 프로젝트의 default_write_vault, 연결 Vault가 하나뿐인 경우 순으로 정하고, 후보가 여럿이면 쓰지 않습니다. 수정 · 폐기는 그 경로가 있는 연결 Vault를 찾습니다. vault-graph는 draft만 만들고 Vault 도구를 실행합니다.stated: publish-draft 검증을 통과하면 published, 아니면 rejected. inferred: review propose가 검토 항목을 만들고 proposed와 review_path를 돌려줍니다. 사람이 review resolve <review_path> --status accepted로 승인해야 발행되고, 그 전에는 회상과 검색에 나오지 않습니다. --status rejected로 거부하면 기억 페이지는 바뀌지 않고 wiki/log.md에 "Review rejected" 한 줄만 남습니다. 후보가 여럿이면 vault_required와 후보 목록.
수집 시점PreCompact · SessionEnd 훅이 Vault 훅 실행기를 부르고, vg가 있으면 실행기가 vg hook capture를 부릅니다. vg는 훅 JSON을 그대로 실행기의 capture --direct에 넘깁니다. 수집할 Vault와 내용은 실행기와 Vault sessions capture가 정합니다.세션 원문이 raw/sessions/에 새 턴만 덧붙여집니다. vg는 결과를 표준 오류에 한 줄로 적고, 실패하거나 20초를 넘기면 종료 코드 3을 내 실행기가 직접 수집하게 합니다. 수집 뒤 색인하지 않고 Graph Home에 쓰지 않습니다.
고정 회상SessionStart 훅이 vg hook session-start를 부릅니다. frontmatter pin: true(불리언)이고 현재 상태인 wiki/ 페이지를 Vault와 상관없이 맨 앞 구획 ## 고정 기억에 넣습니다.고정 기억은 400토큰 예산 안에서 최신순으로 두 줄씩 들어가고, 넘치면 "N개 생략"을 둡니다. 나머지 기억은 모든 연결 Vault를 합쳐 최신순으로 채웁니다. 사용 기록은 순서를 바꾸지 않고 바뀐 · 폐기된 항목 알림의 중복 방지에만 씁니다. 폐기한 페이지는 알림 한 줄로만 나옵니다.

03방향: Local-Graph

이름은 Local-Graph로 맞습니다. 다만 무게는 Local에 둡니다. 모든 처리가 이 컴퓨터 안에서 끝나고 호스팅 서비스, API 키, LLM 호출이 없다는 점이 Honcho와 다릅니다. Graph(관계 추적)는 보조 가치이고, 핵심은 검색과 회상입니다.

제품 정의: vault-graph는 Vault를 기반으로 한 Claude Code용 장기 기억 도구입니다. 기억은 Vault에만 저장하고, 에이전트가 필요한 기억을 Vault 원문, wiki, 코드에서 찾아 출처와 함께 토큰 예산 안에 돌려줍니다. 기억 쓰기는 Vault 자체 도구를 실행해서만 합니다. Vault는 vault-graph 없이도 동작합니다.

코드방향이유연결
방향1활성 SPEC을 "Vault 기반 장기 기억 도구"로 다시 씁니다. 불변성 엔진 v5.0은 보관하거나 별도 SPEC으로 분리합니다.SPEC 목표4("문서와 코드 사이 접점 제거")가 가치3과 정면으로 충돌합니다. README 정의는 이미 새 방향과 맞습니다.결정4 · 발견22

04전체 구조도

실행 중에 움직이는 것은 에이전트, Vault(도구와 파일), vault-graph 세 영역입니다. vault-builder 명령은 설치, 마이그레이션, 프로젝트 연결(link) 때 실행되고, 사용자 범위에 llm-wiki router와 vault-map.json을 남깁니다. 기능 버튼을 누르면 그 기능이 지나가는 상자와 화살표만 남습니다.

결정8 · 변경8에이전트vault-graphVault 도구

세션 중에 "이건 기억해", "그건 이제 틀렸어"라고 하면 에이전트가 vault-graph MCP의 remember, update_memory, retire_memory로 바로 반영합니다. vault-graph는 파일을 쓰지 않고 Vault 도구를 실행하므로, 에이전트는 MCP 하나만 알면 되고 기록은 같은 검증을 거칩니다. Vault의 llm-wiki MCP를 직접 쓰는 길도 남아 있습니다.

  1. 에이전트세 도구 중 하나에 내용, 근거, basis(stated 또는 inferred, 필수)를 넘깁니다.→ 내용 · 근거 경로 · basis
  2. M18 기억 쓰기새 페이지는 vault → default_write_vault → 유일한 연결 Vault 순으로 저장 Vault를 고르고, 후보가 여럿이면 멈춥니다. 수정 · 폐기는 그 경로가 있는 연결 Vault를 찾습니다. 추가 · 수정은 upsert-page, 폐기는 frontmatter만 바꾸는 patch-page draft를 만듭니다.→ draft JSON · 또는 vault_required
  3. 검증 · 발행stated면 publish-draft가 검증하고 기록합니다.→ published 또는 rejected
  4. 검토 대기열inferred면 review propose가 검토 항목을 만듭니다. 사람이 review resolve --status accepted로 승인하면 Vault가 발행합니다.→ proposed · review_path · scratch/review/
