vault-graph · spec 2026-11-25-memory-intent-layers

vg 의도와 기억 층 재설계

세션에 답이 있어도 기본 질의가 세션을 보지 않고, 무관한 wiki 조각을 확인된 근거처럼 돌려주던 문제에서 출발했다. 이 문서는 새 의도, 처리 단계로 다시 나눈 기억 층, 개념 사전 기반 질의, 코드와 기억을 잇는 방식, 개선 순서를 그림으로 보여 준다. 세부 계약과 수용 기준은 spec에 있다.

새 의도

vault-graph는 지난 작업 경험에서 지금 유효한 뜻을 뽑아, Claude Code가 작업하는 순간에 상태와 출처를 붙여 전달한다.

  1. 원천은 작업 경험이다.세션의 대화와 행동, 바뀐 파일, 사용자가 직접 한 말, commit이 원천이다. 원천은 Vault raw/에 저장하고(세션, 자동 기억 노트 사본, 외부 문서), commit은 git에 두고 가리키기만 한다. 원천은 한 번 쓰면 바뀌지 않는다. wiki 페이지는 원천에서 뽑아 확정한 지식을 담고, 고치거나 대체하거나 폐기할 수 있다.
  2. 기억은 상태와 시간을 가진다.모든 기억 단위는 관측, 제안, 확정, 대체됨 중 한 상태와 날짜를 가진다. 질의는 기본으로 지금 유효한 것을 답하고, 요청하면 이력을 답한다.
  3. 뜻은 쓸 때 만들고 읽을 때는 전달만 한다.LLM은 수집 뒤(사실 추출, 드리밍)에만 쓰고 질의 때는 부르지 않는다. vg는 검색 조각이 아니라 정리된 기억 단위를 돌려준다.
  4. 전달 시점은 작업 흐름을 따른다.세션 시작, 사용자 프롬프트(개념이 강하게 걸릴 때만), 요청할 때 기억을 준다. 파일을 읽거나 고칠 때마다 넣지는 않는다. 코드 경로는 기억을 찾는 일급 열쇠다.
  5. 저장 경계는 그대로다.Vault가 저장소이고, 쓰기는 Vault 도구를 거치며, vg는 다시 만들 수 있는 색인만 가진다. SPEC 원칙2~6은 바뀌지 않는다.

이 다섯 문장이 docs/SPEC.md §0 의도를 대신한다 decided · D1

기억 층: 저장 위치에서 기억의 상태로 decided · D2

예전 L1·L2·L3는 기억이 어디에 저장되는지로 나눴다. 그래서 최근 만든 세션 수집, 사실 추출, 드리밍, 검토 승인은 어느 층에도 속하지 못했다. 새 층은 기억이 어떤 상태에 있는지로 나눈다. 기록, 관측, 지식, 현재 상태 네 층이 L1/L2/L3를 대신한다.

"제안" 상태는 Vault 검토 대기열에 있는 지식 후보이고, 수락 전에는 회상과 검색에 나오지 않는다. 그래프는 두 가지 일만 한다. 대체 사슬을 따라가는 일과 개념·코드 경로를 잇는 일이다.

쓰는 흐름: LLM은 여기서만 돈다

질의 흐름: 개념 사전과 층별 답 proposed · D3

NVIDIA Auto Ontology에서 개념 사전, 매핑, 인증, 답 가능성 검사를 가져왔다. 질의 때 LLM이 ReAct로 도는 부분은 가져오지 않았다(의도3).
