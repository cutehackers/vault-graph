# 드리밍 dry-run과 심은 오류 측정 (2026-11-19)

spec `docs/specs/2026-11-19-memory-dreaming/spec.md` §7, 구현 순서 8과 9.

## 요약

- 드리밍은 실제 세션 대기열에서 끝까지 돌았다. Vault와 Graph Home에는 아무것도 쓰지 않았다(dry-run).
- 교환 16개를 판단하는 데 51초, $0.40이 들었고 제안 1개가 나왔다.
- 심은 오류 시험은 16건에서 정밀도 1.0, 재현율 1.0이다. 심은 오류는 실제보다 쉽다.
- 승인율과 승인 전후 비교는 아직 값이 없다. 사람이 실제 제안을 해결해야 생긴다.
- `verify`의 한계 하나를 찾았다. 페이지를 뒤집는 교환이 검색 상위 5개에 없으면 그 페이지는 확인되지 않는다.

## 방법

- 코드는 이 브랜치(`feat/jh/agent-memory-dream`)다.
- 실제 Graph Home과 실제 Vault를 읽기만 했다. `run_dream(..., manual=True, dry_run=True)`을 직접 불렀고, 설정 파일을 만들지 않으려고 묶음 한도만 코드에서 낮췄다.
- 판단은 로그인된 `claude -p --model claude-sonnet-5-5`다. 프롬프트 버전은 `dream-1`이다.
- 실행 전후로 `configs/dream.json`, `dream/`, `logs/dream-runs.jsonl`이 없는 것을 확인했다.
- 세션 내용은 이 보고서에 옮기지 않는다.

## 결과 1: 세션 교환 판단 (D2)

| 값 | 결과 |
|---|---|
| 판단한 교환 | 16개 (묶음 8개씩 두 번) |
| 프롬프트 크기 | 74,031자, 81,731자 |
| 걸린 시간 | 50.8초 (후보와 비교 페이지 찾기 포함) |
| 비용 | $0.395 |
| `none` | 15 |
| 제안할 것 | 1 (`update_memory`) |
| 인용 확인에서 걸러진 것 | 0 |
| 잘못된 답 | 0 |

- 제안 1개는 이미 있는 결정 페이지에 내용을 덧붙이는 것이었다. 새 페이지를 만들지 않았다.
- 인용문은 사용자가 친 한국어 문장 그대로였고 오타도 그대로였다. 인용 확인을 통과했다.
- 덧붙일 글은 대상 페이지의 언어(영어)로 쓰였다. 프롬프트 규칙 3과 맞다.
- 수동 정리 시험(`2026-11-curation-trial.md`)은 후보 40개에서 발행 3개, 추론 제안 0개였다. 이번은 16개에서 추론 제안 1개다. 표본이 작아 비율을 비교할 수는 없다.

## 결과 2: 나중 교환으로 페이지 확인 (D3)

| 값 | 결과 |
|---|---|
| `verify` 후보 만들기 | 53.0초, 후보 44개, 페이지 22개 |
| 판단한 것 | 교환 1개와 `verify` 후보 8개 |
| 걸린 시간 | 58.5초 |
| 비용 | $0.234 |
| `none` | 9 |
| 제안할 것 | 0 |

- 후보를 만드는 53초는 대부분 페이지마다 하는 근거 모드 검색이다. 분리된 작업자에서 돌기 때문에 훅은 기다리지 않는다.
- 찾은 한계: 기본 임베딩 모델을 `e5-small`로 적은 결정 페이지는 지금 사실과 다르다. 그런데 이 페이지에 붙은 나중 교환은 주제만 비슷하고 모델을 바꾼다는 말이 없었다. 판단은 `none`이었고 그 판단은 맞다. 모델을 바꾼 교환이 검색 상위 5개(`VERIFY_SEARCH_LIMIT`)에 들지 못한 것이 원인이다.
- 그래서 D3의 재현율은 검색이 뒤집는 교환을 찾느냐에 달려 있다. 검색 한도를 올릴지는 재고 나서 정한다. 재지 않고 올리지 않았다.

## 결과 3: 심은 오류 시험 (D3)

`tests/benchmarks/measure_dream_verify.py`. 사례는 모두 이 시험용으로 지은 것이다.

| 값 | 결과 |
|---|---|
| 사례 | 16 (한국어 8, 영어 8) |
| 심은 오류 | 8 |
| 음성 대조군 | 8 |
| 찾은 것 | 8 |
| 놓친 것 | 0 |
| 잘못 올린 것 | 0 |
| 코드 확인에서 걸러진 것 | 0 |
| 정밀도 | 1.0 |
| 재현율 | 1.0 |
| 비용 | $0.091 |

- 음성 대조군은 네 가지다. 같은 주제를 묻기만 하는 교환, 페이지와 같은 말을 하는 교환, 이번 한 번만 예외인 교환, 바꾸지 말라고 말한 교환.
- 심은 오류는 "이제 X가 아니라 Y다"처럼 분명하다. 실제 세션은 이보다 흐리다. 이 값은 프롬프트나 모델을 바꿨을 때 비교하는 기준으로만 쓴다.

## 통과 조건 상태

| 조건 (spec §7) | 상태 |
|---|---|
| 드리밍 제안 승인율이 처음 해결된 30개에서 0.7 이상 | 값 없음. `vg dream on` 뒤 사람이 제안을 해결해야 한다. `vg dream status`가 드리밍 제안만으로 센다 |
| 실행당 제안 수, 인용 확인이 거른 수 | dry-run 16개에서 제안 1, 거른 것 0 |
| 대기 교환에만 답이 있는 질문 20개 이상의 context hit 전후 | 값 없음. 질문의 정답 페이지가 승인 뒤에야 생기므로 승인 뒤에 질문을 쓴다 |
| 기존 질문의 context hit이 떨어지지 않음 | 재지 않음. dry-run은 페이지를 바꾸지 않는다. 첫 승인 뒤 `measure_memory_recall`로 잰다 |
| 실행당 비용 | 교환 16개에 $0.40, `verify` 8개에 약 $0.2 |
| 대기 나이 중앙값 | 보고만 한다. 이번에는 바뀌지 않았다 |
| D3 심은 오류 시험 | 정밀도 1.0, 재현율 1.0 |

## 남은 일

1. `vg dream on`으로 켜고 며칠 쓴 뒤 `vg dream status`의 승인율을 본다. 제안은 Vault에서 `review resolve`로 해결한다.
2. 제안이 승인되면, 승인된 페이지를 정답으로 하는 질문 20개를 저장소 밖 질문 파일에 더하고 `measure_memory_recall`을 돌린다.
3. 해결된 제안이 30개가 되면 기본값(꺼짐)을 다시 정한다 (OD2).
4. `VERIFY_SEARCH_LIMIT`을 5에서 올렸을 때 뒤집는 교환을 더 찾는지 잰다.
