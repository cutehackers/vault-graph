# 측정 A-18: 증분 run의 디스크 증가 (2026-11-06)

spec 2026-11-05-session-memory-indexing, 작업 #12. 코드: #3 clone 세대 준비(`46d01e6`), #4 크기·수정 시각 사전 검사(`6d64e37`).

## 방법

`vg index --vault-id vault-graph`를 바뀐 파일 없이 두 번 연달아 실행했다. 실행 전후 홈 볼륨의 남은 공간(`df -k`)을 비교했다. `du`는 APFS clone이 공유하는 블록도 전부 세므로 쓰지 않았다.

| run | 남은 공간 변화 | 실행 시간 | 최대 RSS | 바뀐 문서 | 벡터 upsert |
|---|---|---|---|---|---|
| 1 | 218MB 늘어남 | 16.8초 | 0.87GB | 0 | 0 |
| 2 | 0.03MB 줄어듦 | 16.9초 | 0.86GB | 0 | 0 |

- run 1은 그 전 run(복사로 만든 세대)이 정리되면서 공간이 돌아왔다.
- run 2가 clone 세대 준비만으로 한 run의 증가량이다.

## 판단

- 목표7 "증분 run 디스크 증가 50MB 이하(지금 약 650MB)"를 충족했다. 관측값은 0.03MB다.
- 바뀐 파일이 없는 run에서 문서 54개를 모두 그대로 두었다. Vault 파일을 열지 않는 것은 단위 테스트(`tests/test_metadata_precheck.py`)로 확인했다.
- 남은 고정 비용은 약 17초다. 그래프 전체 재조정(S13, 작업 #30)과 벡터 계획이 대부분일 것으로 본다. #30과 #35에서 다시 잰다.
