## 2. 원인

1. 발견1. 한국어 페이지 쏠림. 위키 220쪽 중 본문이 한국어인 페이지는 personal의 3쪽뿐이다. 이 3쪽이 지식 모드 113문항 중 75문항에서 상위 5위에 들고, 지식 모드 실패 22문항 모두에 들어 있다. 주제와 상관없이 한국어 질문이 한국어 본문과 벡터가 가까워지는 언어 쏠림이다.
2. 발견2. 세션 사본. 같은 대화를 이어 쓴 세션 파일들이 같은 교환을 그대로 담는다. `_fold_duplicate_content`(`src/vault_graph/retrieval/search/evidence_result_assembly.py:346`)는 다른 Vault 사이의 같은 문서만 접어서, 같은 Vault 안의 사본이 상위 자리를 채운다.
3. 발견3. 대체된 페이지 접힘. `_fold_replacements`(`evidence_result_assembly.py:295`)는 supersedes 묶음에서 가장 높은 페이지만 남긴다. 옛 결정을 직접 묻는 질문(L1B-021, L1B-037)은 정답이 버려진다.
4. 발견4. 맞는 파일, 틀린 교환. 세션 실패 15문항 중 12문항은 정답 세션 파일이 상위 4위 안에 있다. 그중 5문항(L1C-011, L1C-019, L1C-024, L1C-025, L1C-039)은 1위가 정답 교환의 바로 앞이나 뒤 교환이다.
5. 발견5. 방안B의 전제는 이미 채워져 있다. 위키 220쪽 모두에 summary가 있고 페이지 카드와 키워드 표에 이미 들어간다. 다만 한국어 summary는 4쪽이고 aliases는 0쪽이다.
6. 발견6. 지식 모드가 보지 않는 `scratch/reports/`만 정답인 문항이 2개 있다(L1B-022, L1B-023).

## 3. 방안별 실험 (기록된 순위를 다시 합친 시뮬레이션)

시뮬레이터는 기준값 192문항의 순위를 오차 없이 재현한다. 기준값은 전체 recall@5 0.792, 시험용 0.802, MRR 0.655다.

| 방안 | 전체 | 시험용 | 좋아짐 / 나빠짐 | 판단 |
|---|---:|---:|---|---|
| 방안A 한국어+영어 표현, 같은 가중치 | 0.844 | 0.865 | +20 / −10 | 효과가 가장 크다. 나빠진 것은 대부분 세션 질문이다 |
| 방안A + 같은 Vault 세션 사본 접기 | 0.880 | 0.885 | +23 / −6 | |
| 같은 Vault 세션 사본 접기만 | 0.823 | 0.833 | +6 / −0 | spec 밖. 작은 변경이다 |
| 방안D RRF 상수 K=20 | | | +6 / −3 | 측정 잡음과 구분되지 않는다 |
| 방안D 벡터 가중치 1.5 | | | +4 / −2 | 측정 잡음과 구분되지 않는다 |
| 한국어 페이지 3쪽 점수 낮추기 | | | +7 / −0 | 고정 목록이라 과적합이다. 방안A 위에서는 효과가 0이다 |

- 방안A의 영어 표현은 실험용으로 에이전트가 썼다. 그 에이전트는 실패 분석에서 정답 페이지를 봤으므로 이 숫자는 높게 나왔을 수 있다. 작업 11에서 정답과 결과를 보지 않는 별도 에이전트가 표현 묶음을 다시 써서 잰다.
- 영어 쪽 가중치 0.5는 시험용을 포함해 잰 값이라 채택 근거로 쓰지 않는다. 가중치는 개발용으로만 정한다.
- 방안C는 정답이 상위 30 안에 있는 실패가 26/40이라 상한은 크다. 모델(bge-reranker-v2-m3, 568M)의 이 Mac 검색 시간은 아직 재지 않았다.
- 방안B와 Kiwi 형태소는 근거가 없어서 재지 않았다. 임베딩 교체는 4.2.5 조건을 만족하지 않는다.

## 4. 방안 선택

1. 결정16. 방안A(작업 11, 12)를 먼저 진행한다. 지식 검색은 한국어 원문과 영어 표현을 함께 넣도록 도구 설명에 적는다. 세션 검색에는 영어 표현을 권하지 않는다. 표현 2개와 4개에서 p95가 1초 안인지 잰다.
2. 결정17. 같은 Vault 안 세션 교환 사본 접기와 대체된 페이지를 근거로 붙이기를 새 작업 25로 더한다.
3. 결정18. 방안C(작업 21)는 방안A와 작업 25 뒤에 층1을 다시 재서 판정한다. 남은 실패가 주로 6~30위 순위 손실이고, 재정렬을 넣은 p95가 1초 이하일 때만 넣는다.
4. 결정19. 방안D(작업 22)는 건너뛴다. RRF 조정 효과가 ±3문항으로 잡음 수준이고 Kiwi는 키워드 쪽 손실 근거가 없다. 방안B(4.2.2)는 S7 보강으로 한국어 summary와 aliases가 생긴 뒤 작업 16에서 잰다. 임베딩 교체 spec은 열지 않는다.
5. 한국어 페이지 점수 낮추기와 세션 결과를 파일 하나로 묶기는 채택하지 않는다. 앞의 것은 과적합이고, 뒤의 것은 결과 모양을 바꾼다.

다음 근거가 나오면 선택을 바꾼다.

- 질의 기록(결정13)에서 에이전트가 queries를 거의 쓰지 않으면 방안A는 실제 사용에서 효과가 없다. 그때는 방안C를 앞당긴다.
- 재정렬 30개가 0.5초 안에 끝나면 방안C를 방안A와 나란히 진행한다.
- 방안A 뒤 후보 손실이 실패의 절반을 넘으면 임베딩 교체 spec을 연다.

## 5. 사람이 정할 측정 규칙

1. 질문1. `scratch/reports/`만 정답인 2문항(L1B-022, L1B-023)을 층1에서 뺄지 정한다.
2. 질문2. 정답 교환의 바로 앞이나 뒤 교환을 정답으로 인정할지 정한다. 인정하면 세션 5문항이 맞는다.
