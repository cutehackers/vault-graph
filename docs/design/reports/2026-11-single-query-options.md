# 질문 하나로 재는 검색 품질: 방안 비교 (2026-11-12)

목표 문서 `docs/specs/2026-11-11-search-and-memory-quality-2/research/2026-11-12-fundamental-quality-goal.md`의 완료 기준 1에 쓰는 근거다. 코드 기준은 `130264c`, 임베딩 모델은 multilingual-e5-small이다. 문항은 id와 개수로만 적는다.

상태: 4절의 처음 제안(언어 성분 빼기)은 사용자가 받지 않았다. 사용자가 더 근본적인 방안을 요청했고, 모델 후보 2개 내려받기와 측정을 승인했다(2026-11-12). 7절이 그 결과다. 기본 모델 교체는 사용자가 LongMemEval 조건을 붙여 승인했고, 조건을 넘어 확정했다(8.1). 8절이 최종 측정이다. 사용자가 8절의 변경 네 가지(모델 교체, 세션 색인 수정 두 건, 사본 접기)를 최종 승인했다(2026-11-13).

## 1. 왜 다시 비교하나

- 손실 보고서(`2026-11-search-loss-classification.md`)는 방안A(여러 표현 질의)를 먼저 하기로 했다. 방안A는 에이전트가 영어 표현을 함께 넣어야 효과가 난다.
- 목표 문서는 검색 목표를 질문 하나만 넣어서 재도록 정했다. 그래서 방안A는 목표 판정에 쓸 수 없다.
- 원인(한국어 질문이 주제와 상관없이 한국어 본문과 가까워지는 것)을 검색 안에서 줄이는 방안이 필요하다.

## 2. 원인을 다시 잰 결과

층1 지식 모드 문항 113개(한국어 질문 80, 영어 질문 33)의 신호별 상위 10개를 셌다. 지식 모드가 읽는 벡터는 476개이고 그중 한국어 본문 조각은 22개(4.6%)다.

| 측정 | 값 |
|---|---:|
| 벡터 상위 10개 중 한국어 본문 조각 | 53% (598/1,130) |
| 실패 문항의 벡터 상위 10개 중 한국어 본문 조각 | 61% (128/210) |
| 키워드 상위 10개 중 한국어 본문 조각 | 21% (221/1,059) |
| 실패 문항의 키워드 상위 10개 중 한국어 본문 조각 | 45% (79/177) |
| 상위 5개 결과에 한국어 본문 결과가 든 문항 | 80/113 |
| 실패 21문항 중 상위 5개에 한국어 본문 결과가 든 문항 | 21/21 |

- 발견1. 쏠림의 대부분은 벡터 신호에서 온다. 전체 조각의 4.6%가 벡터 상위 10개의 53%를 차지한다.
- 발견2. 키워드 신호도 쏠린다. 한국어 낱말은 한국어 본문에만 있어서다. 이것은 검색 쪽에서 번역 없이 고칠 수 없고, 페이지에 한국어 summary와 aliases가 있어야 줄어든다.
- 발견3. 한국어 조각 평균 벡터와 영어 조각 평균 벡터의 코사인은 0.977이다. 두 평균의 차이가 언어를 나타내는 성분이다.

## 3. 방안 비교

개발용 96문항(wiki 66, 세션 30)으로만 쟀다. 시험용은 쓰지 않았다. 층2는 180문항 전체다. 실험은 색인된 벡터와 질문 벡터를 메모리에서 바꿔 평가 도구를 그대로 돌렸다. 저장소 코드는 바꾸지 않았다.

- 옵션1: 조각을 본문의 한글 비율로 한국어와 영어로 나눈다. 언어마다 색인 전체 조각의 평균 벡터를 구해 그 언어 조각에서 뺀다. 질문 벡터에서도 질문 언어의 평균을 뺀다. 종류별 개발용 결과는 title 15/15, 의역 14→17, 결정 13→15, 방법 11→13이다. 세션은 22→20이다.
- 옵션2: 한국어 평균과 영어 평균의 차이 방향 하나만 모든 벡터와 질문 벡터에서 뺀다. 의역 14→15, 결정 13→14, 방법 11→13, 세션 22→24다. 어느 종류도 나빠지지 않았다.
- 옵션1과 옵션2 모두 새 모델과 다시 색인이 필요 없다. 평균은 색인된 벡터에서 계산하므로 같은 색인이면 같은 결과다.
- 옵션1과 옵션2의 전체 차이(1문항)와 세션 차이(4문항)는 개발용 문항 수로는 잡음과 구분되지 않는다. 한 문항이 종류별로 3~7점이다.
- 옵션4는 `bge-reranker-v2-m3`(568MB) 내려받기가 필요하다. 내려받지 않아서 재지 않았다. 순위 손실에만 효과가 있고 검색 시간이 는다.
- 옵션5는 모델 내려받기와 전체 다시 색인이 필요하고 spec 3의 Non-goal이다. 재지 않았다.
- 키워드 상위 10개의 한국어 비율은 어느 옵션에서도 그대로다(개발용 0.20). 발견2대로 페이지 보강(S7)이 맡는다.

## 4. 제안

1. 제안1. 옵션1과 옵션2 중 하나를 검색에 넣는다. 둘 중 무엇으로 할지는 작업 25(세션 사본 접기, 대체된 페이지 근거)를 넣은 뒤 개발용으로 다시 재서 정한다. 시험용은 마지막에 한 번만 잰다.
2. 제안2. 작업 25(결정17)는 그대로 진행한다. 세션 사본과 대체된 페이지 접힘은 언어와 다른 원인이다.
3. 제안3. S7(쓰는 시점 summary, aliases)과 S8을 진행한다. 도구 설명에 "사용자가 쓰는 언어의 summary와 aliases를 함께 적는다"를 넣는다. 발견2의 키워드 쏠림을 쓰는 시점에서 줄인다.
4. 제안4. `memory-backlog` 브랜치 backlog의 MEMORY-01(`remember`가 비슷한 기존 페이지를 결과에 붙인다)을 S7에 더한다. 같은 사실이 다른 페이지로 다시 저장되면 검색 상위 자리를 나눠 갖는다. 그 backlog의 나머지 항목은 검색 순위와 거리가 있어 이 작업에 넣지 않는다.
5. 제안5. 옵션4와 옵션5는 지금 하지 않는다. 제안1~3 뒤 시험용 결과가 목표에 못 미치고 남은 실패가 순위 손실이면 옵션4를 내려받아 잰다.
6. 제안6. 방안A(S6)는 목표 판정과 분리한다. 도구 기능으로 넣을지는 따로 정한다.

## 5. 원인이 줄었는지 재는 방법

완료 기준 3에 쓴다. 변경 전후로 아래를 같은 문항에서 잰다.

1. 지식 모드 벡터 상위 10개 중 한국어 본문 조각 비율(지금 0.53).
2. 지식 모드 실패 문항 중 상위 5개에 한국어 본문 결과가 든 문항 수(지금 21/21).
3. 세션 모드 상위 5개 중 같은 교환의 사본이 차지한 자리 수.
4. 대체된 페이지가 정답인 문항의 최종 순위(L1B-021, L1B-037).

## 6. 실험 파일

세션 임시 폴더에 있다. 층1 문항별 결과가 들어 있어 저장소에 넣지 않는다.

## 7. 임베딩 모델 교체 측정 (2026-11-12)

원인은 지금 모델이 내용보다 언어를 크게 반영해 벡터를 만드는 것이다. 언어 성분 빼기는 그 결함을 검색 때 보정하고, 모델 교체는 원인을 직접 바꾼다. 그래서 모델 후보를 쟀다.

### 7.1 방법

- 같은 Vault 6개를 모델마다 새 Graph Home에 처음부터 색인했다. 기본 모델 설정과 실제 Graph Home은 바꾸지 않았다. 후보 preset은 실험 스크립트에서만 등록했다.
- 코드는 작업 25(세션 사본 접기, 대체된 페이지 근거)를 넣은 상태다.
- 개발용 96문항만 쟀다. 색인 시간은 다른 작업이 함께 돌던 Mac에서 잰 값이라 넉넉히 본다.
- 후보 설정은 모델 카드에서 확인했다. e5-base는 평균 풀링과 `query: `/`passage: ` 접두사, arctic-m은 CLS 풀링과 질문 쪽 `query: ` 접두사다. 둘 다 768차원, int8 ONNX다.

### 7.3 판단

1. 발견4. arctic-m은 보정 없이 한국어 쏠림을 0.57에서 0.13으로 줄인다. 모델을 바꾸면 원인이 줄어든다는 것이 확인됐다.
2. 발견5. arctic-m 위에 언어 성분 빼기를 더해도 점수가 오르지 않는다(86 → 85). 보정은 필요 없다.
3. 발견6. 세션 질문은 arctic-m만 뚜렷하게 오른다(22 → 26). 언어 성분 빼기는 세션에서 효과가 작다(23~24).
4. 발견7. e5-base는 쏠림이 0.34로 남고 세션이 오르지 않는다. 후보에서 뺀다.
5. 발견8. 비용은 전체 색인 시간이 2.7배(468초 → 1,246초), 내려받기가 311MB다. 최대 메모리와 검색 시간은 지금과 같은 수준이다. 2026-11-04에 arctic-l이 끝나지 않았던 것과 달리 21분에 끝난다.
6. 개발용 전체 점수에서 arctic-m(86)과 e5-small+옵션1(85)의 차이는 1문항이라 잡음과 구분되지 않는다. 고르는 근거는 점수가 아니라 원인을 모델에서 없애는지, 보정 코드가 필요한지, 세션에서도 듣는지다.

### 7.4 제안 (4절을 바꾼다)

1. 제안7. 기본 임베딩 모델을 `Snowflake/snowflake-arctic-embed-m-v2.0`(int8)으로 바꾼다. 언어 성분 빼기는 넣지 않는다.
2. 제안8. 교체 전에 LongMemEval 150문항(목표9)을 arctic-m으로 잰다. 기준값 0.78에서 0.01 넘게 떨어지면 교체하지 않고 다시 보고한다.
3. 제안2, 제안3, 제안4(작업 25, S7·S8, MEMORY-01)는 그대로다. 제안1, 제안5는 거둔다.
4. spec은 3절 Non-goal의 "임베딩 모델 교체"와 4.2.5를 고치고 결정을 더한다.

아직 재지 않은 것: LongMemEval, 시험용 문항, 벡터 저장소 크기(768차원이라 지금보다 커진다), 조용한 Mac에서의 색인 시간.

## 8. 최종 측정 (2026-11-12)

### 8.1 모델 교체 조건

LongMemEval-S 150문항을 `arctic-m`으로 쟀다. recall_all@5는 0.7733, recall_any@5는 0.9667이다. 기준값 0.78에서 0.0067 내려갔고 허용 범위 0.01 안이다. 조건을 넘어 기본 모델을 `arctic-m`으로 바꿨다(spec 결정20). 기준값 파일은 0.78 그대로 둔다.

### 8.2 측정 중 찾아 고친 것: 색인에서 빠진 세션 교환

모델을 바꾼 뒤에도 세션 검색이 목표3에 못 미쳤다(0.83, 0.90). 개발용 세션 실패 4문항을 보니 2문항은 정답 교환이 색인에 없었다. 시험용 문항은 보지 않았다.

- 원인1: 예전 형식(v1) 세션의 본 대화 교환이 새 형식(v2) 서브에이전트 교환과 시간이 겹치면 색인에서 빠졌다. v2 파일에는 그 본 대화가 없다. 14,803줄 파일이 1,178줄까지만 색인된 예가 있다.
- 원인2: v2 파일이 교환의 뒷부분만 가진 경우(`continued=1`)에도 교환 전체 시간으로 v1 교환을 뺐다. v2 파일에 턴 하나만 있는데 v1 대화 한 시간 분량이 빠진 예가 있다.
- 수정: 같은 범위(본 대화끼리, 같은 서브에이전트끼리)일 때만 뺀다. 이어진 사본은 파일에 실제로 있는 턴이 v1 교환 전체를 덮을 때만 뺀다(`indexing/ingestion/session_group.py`, `session-group-v3`).
- 결과: 색인된 세션 교환이 Vault 2개에서 78개 늘었다(vault-graph 566→604, sgp-981-app 2,079→2,119). 세션 recall@5는 50→54문항이 됐다.
- 이 규칙은 spec `2026-11-05-session-memory-indexing` §4.2.7에 적혀 있다. 사용자 승인(2026-11-13)을 받아 그 문단을 고쳤다.

### 8.5 남은 것

1. 목표7: 정리 대기 세션 교환의 나이 중앙값이 7.3일이다. 사용자가 있는 세션에서 "기억 정리"를 돌려야 내려간다(spec 결정12). 실제 Vault에 쓰는 일이다.
2. 목표4: 0.92(34/37)로 목표 0.95(35/37)에 1문항 모자란다.
   - 질문 파일은 지워져 있었다. 2026-11-07 세션 기록에 남은 생성 스크립트로 42문항을 다시 만들었다. 프로젝트 섞임 5문항은 그때 보고서대로 내용이 같은 personal 사본도 정답으로 받았다(5개 모두 파일이 같다는 것을 확인했다).
   - 같은 Vault 상태에서 `e5-small`은 0.89(33/37)다. 0.95는 2026-11-07의 Vault에서 잰 값이고 그 뒤 Vault가 커졌다. 모델 교체는 1문항을 더했다.
   - 놓친 3문항은 두 모델 모두 한국어 본문 페이지 두 개가 상위에 올라온다. 키워드 쪽 쏠림(8.4)이고, 정답 페이지에 한국어 summary와 aliases가 있어야 줄어든다. 기억 정리 때 채우는 값이다(spec 4.3.2).

사용자 승인을 받아 실제 Vault에서 기억 정리를 했다. 대상은 신호(교정, 결정)가 붙은 세션 교환 39개와 13일 넘은 교환 52개, 모두 91개다. 에이전트가 교환을 읽고 처리안을 만들었고, 사용자에게 목록을 보인 뒤 썼다.
