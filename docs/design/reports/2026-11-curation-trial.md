## 방법

- Claude Code 세션을 따로 띄워 "기억 정리해"라고 보냈다. 그 세션의 vault-graph MCP는 이 브랜치 코드로 돌았다.
- 쓰기는 실제 Vault에 갔다. Graph Home은 실제 것의 복사본을 썼다. 실제 Graph Home은 바뀌지 않았다.
- 사람이 실행과 승인 판단을 에이전트에게 맡겼다. 그래서 세션은 `claude -p`로 돌렸고 사람이 중간에 답하지 않았다.
- `inferred` 제안은 0건이었다. 그래서 검토 대기열에서 사람이 승인할 항목이 없었다.
- 정리를 두 번 돌렸다. 1회차에서 후보 고르기 버그 셋을 찾았고, 고친 뒤 2회차를 돌렸다.

## 1회차에서 찾은 문제와 고친 것

1. 세션 교환 후보 16건이 모두 `correction` 신호였다. 그런데 실제 사용자 교정은 하나도 없었다.
   - 원인: v1 세션 파일에서 사람 턴이 아닌 글을 사람 턴으로 읽었다.
     - 서브에이전트에게 준 지시문: 10건
     - 컨텍스트 압축 뒤 요약문과 앱 안내문: 4건
     - `<command-message>`로 시작하는 명령 글: 1건
   - 이 글들에 "fix", "do not" 같은 단어가 있어 교정 신호로 잡혔다.
   - 고침(`9fbe9f7`): spec §4.2.2의 사람 턴 규칙을 정리 후보에도 적용했다. v2는 `scope=subagent:` 교환의 사람 턴을 읽지 않는다.
2. 같은 교환이 후보로 세 번 나왔다.
   - 원인: 이어받거나 갈라진 세션 파일 세 개가 앞 턴을 그대로 담고 있었다.
   - 고침(`9fbe9f7`): 시작 시각과 사람 턴 글이 같은 교환은 한 후보로 낸다.
3. 병합·폐기·brief 후보가 한 번도 나오지 않았다.
   - 원인: 신호 없는 세션 교환 약 1,000건이 기본 20개를 모두 차지했다.
   - 고침(`f2221f3`): 신호 없는 세션 교환을 모든 종류 뒤로 보냈다.

## 2회차에서 찾은 문제와 고친 것
