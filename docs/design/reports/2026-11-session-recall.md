# 측정 A-8·A-9: 세션 문서 형식과 조각기별 세션 검색 (2026-11-06)

spec 2026-11-05-session-memory-indexing, 작업 #31. 코드: `feat/jh/session-memory-indexing`(v1·v2 조각기 `3cac571`, 세션 묶음 `8caee37`, 이어 연 세션 id 수정 `edb9fea`). vault-builder: `feat/jh/session-memory-requests`(요청S10 `9f19b1e`, `40d05cd`).

## 방법

- 실제 vault-graph Vault(세션 v1 파트 28개, 세션 21개)를 작업용 폴더에 복사했다. 실제 Vault와 실제 Graph Home은 바꾸지 않았다(실행 전후 세션 파일 수 28 그대로).
- (c)용 사본은 vault-builder 브랜치의 Vault 도구로 바꾸고, `vg session export`로 만든 정규화 파일을 `sessions capture --normalized --rerender`로 다시 써서 세션마다 v2 파트를 더했다. 기존 v1 파트는 그대로 둔다.
- 단계별 Graph Home 셋을 새로 만들었다. (a) 설치된 릴리스 vg + v1만 있는 사본, (b) 이 브랜치 + v1만 있는 사본, (c) 이 브랜치 + v1·v2 사본.
- 질의: `tests/benchmarks/measure_session_recall.py`, `vg search --mode evidence --vault-id vault-graph`, 결과 20개.

## 질의 세트 (대리 세트, spec과 다름)

spec은 사람이 기대 교환을 고른 한국어 질의 40~60개를 요구한다. 이번에는 사람이 고르지 않은 **대리 세트**를 썼다. v2 파일의 본 대화 교환 126개 중 50개를 고정 시드로 뽑고, 각 교환의 첫 사람 턴에서 단어 3~14번째를 질의로 썼다(`kind: paraphrase`). 기대 위치는 그 교환의 v2 줄 범위와, 같은 시각의 v1 사람 턴 위치(50개 중 48개)다. 질의와 결과 원문은 저장소 밖에만 있다.

이 세트는 v2에 유리하다. v2 임베딩 입력 머리말 `Question: <사람 턴 앞 80자>`가 질의를 만든 원문과 겹치기 때문이다. 사람이 만든 질의 세트로 다시 재야 결론이 된다.

## 측정 중 찾아 고친 것

- 위험A10이 실제로 있었다. Claude Code가 이어 연 세션은 파일 이름(훅이 알리는 세션 id)과 기록 안 `sessionId`가 다르다. v1 수집은 파일 이름을, vg adapter는 기록 id를 써서 같은 세션의 v1·v2가 다른 묶음이 되었고 v1 교환 2,097조각이 겹침 제외되지 않았다. adapter가 파일 이름을 세션 id로 쓰고 기록 id를 `parent_session_id`로 남기게 고쳤다(`edb9fea`). 고친 뒤 남은 v1은 5조각이다.
- 측정 도구가 `-`로 시작하는 질의를 옵션으로 읽었다. `--` 뒤에 넘기게 고쳤다.
