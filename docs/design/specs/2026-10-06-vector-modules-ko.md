# 임베딩·벡터 검색·벡터 인덱싱 독립 모듈

사용자가 승인한 2차 리팩터링 목표를 구현하는 계약이다. 기존 Vault Graph의 결과·저장 형식과 읽기 전용 경계를 유지한다. 기준 커밋은 `aa130b6`, 기준선은 전체 1,313개 통과·조건부 1개 생략이다.

## 의존 방향과 책임

- `nolemy-text-embeddings` / `text_embeddings`: 텍스트→벡터, 모델 정보와 출력 검증. FastEmbed 구현은 선택 설치한다. 필수 제공자 계약은 `model_spec()`·`embed()`이다.
- `nolemy-vector-search` / `vector_search`: 이름으로 구분한 컬렉션의 벡터 저장·삭제·필터 조회·목록·건강 상태. Chroma 구현은 선택 설치한다. 메타데이터는 불투명한 스칼라 값이다.
- `nolemy-vector-index` / `vector_index`: 준비된 텍스트 항목의 변경 계획, 배치 임베딩, 갱신. 앞선 두 계약을 이용한다.
- `vault_graph.vault_adapter`: 문서 수집과 청크 생성 이후 식별자·텍스트·지문·범위 변환, 오프라인 정책, 근거 조회, 상태·세대 발행·복구를 소유한다. 기존 가져오기 경로는 호환 진입점으로 유지한다.

독립 패키지는 Vault/그래프 패키지를 가져오거나 Vault 필드를 해석하지 않는다. 기존 VectorStore 계약은 Vault 계층에서 보존한다.

## 벡터 검색 계약

`CollectionSpec`은 컬렉션 이름·차원·거리 척도와 불투명한 기대 메타데이터를 지정한다. 이번 구현의 거리 척도는 기존 cosine이다. 모델별 컬렉션 이름과 메타데이터는 호출자가 지정한다. 차원이 같아도 다른 모델 공간을 자동으로 합치지 않는다.

`StoredVector`는 레코드 ID·벡터·메타데이터, 결과는 ID·점수·순위·메타데이터를 반환한다. 필터는 결과 상한을 적용하기 전에 평가한다. 조회는 명시한 컬렉션만 이용한다. 삭제는 컬렉션·레코드 ID와 기대 메타데이터로 한정한다. 저장 경로·보조 테이블명·접두사·호환성 검사 값은 설정으로 받는다. 기존 이름을 선택하는 책임은 Vault 어댑터에 있다.

읽기 전용 접근은 Chroma 클라이언트를 생성하거나 파일을 만들지 않는다. 읽기 전용 검색의 동점 순서는 명시적으로 지정할 수 있으며 Vault에서는 기존 순서를 유지한다.

## 인덱싱 계약

`IndexItem`은 collection_id·item_id·record_id·입력 텍스트·변경 지문을 제공한다. `IndexedItem`은 같은 식별자와 벡터 공간 식별자·지문을 보관한다. ID와 지문은 호출자가 결정하며 문서·경로·역할을 코어가 해석하지 않는다. 벡터 공간은 모델명·버전·차원·명세 버전 및 호출자가 관리하는 전처리 계약으로 구분한다.

계획은 논리적인 입력·삭제 범위인 `collection_ids`와 `input_kind`를 필수로 받는다. 이 범위는 모델별 물리 Chroma 컬렉션명과 다르다. 호출자는 범위의 모든 모델 공간에 걸친 현재 목록을 제공해야 한다. Vault에서는 기존 QueryScope로 필터링한 청크와 저장 목록만 전달하며 부분 경로를 전체 Vault 목록으로 취급하지 않는다. `snapshot`은 선택한 범위의 전체 목록임을 호출자가 선언하며 누락 레코드 삭제를 허용한다. `changes`는 부분 변경이며 입력에 없는 항목을 삭제하지 않는다. 선택 범위 밖의 입력과 저장 행은 거부한다. 모델 변경 시 해당 입력 항목의 이전 공간 레코드를 정리한다. 전체 재색인은 같은 항목도 다시 임베딩한다.

계획 생성은 저장·모델 다운로드 없이 수행한다. 실행은 모든 필요한 임베딩의 ID·개수·모델을 검증한 뒤 저장소를 호출한다. 실행 중 저장소가 실패하면 실패를 반환하고 재시도할 수 있지만, 일반 저장소의 롤백이나 원자적 커밋은 보장하지 않는다. 실행은 현재 저장 목록으로 계획을 다시 계산해 동일한 경우에만 진행한다. 직접 구성한 잘못된 계획과 오래된 계획은 쓰기 전에 거부하며 실패 후에는 새 계획으로 재시도한다. 이 검사는 원자적 비교·갱신이나 잠금이 아니며 동시 작성자 직렬화는 호출자의 책임이다.

## Vault 호환성

기존 벡터 ID·컬렉션명·Chroma 스키마·보조 payload 테이블·모델 명세·점수·순위·경고·리비전을 유지한다. 청크 지문은 현재 비교 필드 전체를 반영한다. 전체 조회 범위와 삭제 허용 범위는 QueryScope 변환에서 결정한다. 기존 MetadataStore에서 검색 근거를 조회한다. 쓰기 대상은 기존처럼 비활성 스테이징 세대이다. 실패한 스테이징 세대는 공개하지 않는다. 기존 세대 발행 절차만 활성 데이터를 전환하며 코어가 Vault 원본을 수정하지 않는다.

## 완료 검증

독립 설치 환경에서 세 패키지 각각의 공개 API와 텍스트→색인→검색 연동을 실행한다. 기존 전체 회귀 검사와 CLI/MCP/HTTP 계약, 읽기 전용 해시, 재실행·모델 변경·부분 입력·범위별 삭제·실패 재시도를 검증한다. 각 단계 독립 리뷰의 지적을 해결한다. 설치·검증·한계는 완료 보고서에 기록한다. PyPI 업로드·커밋·푸시는 이번 목표에 포함하지 않는다.
