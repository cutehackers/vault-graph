# 측정 방법과 사용자 데이터

조사일: 2026-11-04. 출처는 저장소 코드와 `$HOME/.vault-graph`의 읽기 전용 파일이다.

## 측정1

- 정의: `docs/SPEC.md:171-175`. 같은 질문 20개를 Vault 검색과 `vg search`(상위 5개)에 넣고 상위 5개 적중률과 시간을 비교한다.
- 상세: `docs/specs/2026-10-29-local-graph-memory-layer/spec.md:106-116`. 질문 파일은 JSONL `{id, question, expected[]}`이고, 질문마다 3번 실행한다. 질문과 결과는 저장소에 넣지 않고 합계만 `docs/design/reports/`에 남긴다(`spec.md:55`).
- 실행기: `tests/benchmarks/measure_vault_search_parity.py`(`TOP_K=5`, `RUNS_PER_QUESTION=3`, `:30-32`). `vg search --graph-home ... --format json`을 하위 프로세스로 실행한다. 저장소 안 출력 폴더는 거부한다(`:211`).
- 모델 비교 기능은 없다. 모델마다 Graph Home을 따로 두고 실행기를 돌려야 한다.
- 결과는 한 번도 기록되지 않았다. 1차-1, 1차-6, n차-4가 모두 미완료다(`docs/TODO.md:37,43,54`).

## 사용자 Vault 구성

Graph Home `$HOME/.vault-graph`에 Vault 6개가 등록되어 있다.

| Vault | 조각 수 | 문서 수 |
|---|---|---|
| vault-graph | 15,677 | 41 (조각 15,273개가 세션 원문 11개에서 나옴) |
| personal | 3,710 | 350 |
| sgp-981-app | 2,931 | 29 |
| vault-builder | 2,699 | 27 |
| bake | 716 | 25 |
| 981park-flutter-app | 391 | 23 |

- 전체 26,124조각, 벡터 저장소 176MB. 조각 평균 길이는 13~104토큰으로 짧다.
- 언어: wiki 페이지는 거의 영어다. 한국어는 세션 원문과 보고서에 글자 수 기준 5~26% 섞여 있다(한글 한 글자가 영어 2~3글자 정도의 뜻을 담으므로 실제 비중은 더 크다). 코드는 본문의 6~31%, 경로는 최대 33%다.
- 즉 검색 대상의 대부분은 coding agent 세션 원문이다. 영어 도구 출력, 코드, 경로 사이에 한국어 대화가 섞여 있고, 질문은 주로 짧은 한국어다.

## 속도

- 기록된 소요 시간은 없다. 로그의 세대 시각 차이로 보면 MiniLM은 초당 약 110~165조각을 만든다.
- 이 속도라면 전체 26k조각을 다시 임베딩하는 데 약 2.5~4분이 걸린다(추정, 측정 안 함).
